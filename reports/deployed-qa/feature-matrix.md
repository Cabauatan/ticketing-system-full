# Deployed functional QA matrix

Prepared from current routes, controllers, Pinia stores and installed-procedure migration sources on 2026-10-11 (Asia/Singapore). Backend: `https://ticketing-system-full.onrender.com`; frontend: `https://ticketing-system-full.pages.dev`.

**Status of every case below: NOT YET LIVE TESTED by this source-audit agent.** A source expectation is not a production pass. Record actual URL, role, response status, visible outcome, fixture ID and screenshot separately during execution. Read-only source inspection; no database, network, credentials or mail delivery was performed for this matrix.

## Execution rules and fixtures

- Use an existing signed-in verified Superadmin for read-only navigation, exports and permission checks. Do not change its password, email, avatar, roles, 2FA or passkeys.
- Use synthetic records named `QA-20261011-<unique suffix>` for ticket, asset and category writes. An existing category from `GET /api/tickets` avoids creating a global category.
- Cross-account/security cases need verified dedicated requester A/B, agent A/B, dispatcher, admin and inventory manager accounts. Reuse existing test-only accounts if available. Do not change real users' roles. Test role combinations both orders: `["requester","agent"]`, `["agent","requester"]`, `["inventory_manager","dispatcher"]`, `["dispatcher","inventory_manager"]`.
- Request all APIs with `Accept: application/json`, authenticated session cookies and mutations' `X-CSRF-TOKEN` from `GET /api/csrf-token`. Vue already handles this. Cross-origin cookie/CORS and a real browser session must be checked separately from HTTP clients.
- Throttles: general protected API 60/minute; chat reads/presence 120/minute; extra write/download limits 6–30/minute. Pace tests; do not deliberately exhaust global limits on real users.
- Capture returned `id` and re-read current `version` before each versioned write. Deliberate stale-version tests use synthetic records only.
- Preserve audit records. Final synthetic tickets can be closed, equipment can be returned then retired with a QA note, and consumable quantities reconciled with explicit stock transactions. No ticket/asset/category delete API exists. Keep a fixture ledger rather than deleting production rows. Notification-read changes and uploaded proof files have no reversal API.

## Definite source findings and unconfirmed deployment risks

1. **Multiple-role SQL gaps:** several existing deployed-procedure sources use only `users.role` for global staff scope, agent choice or internal-note visibility while PHP permissions union `user_roles`. Secondary dispatcher/admin/agent can receive UI permission but missing rows/403/404 or missing agent options. Normal AdminUserRole writes canonicalize the strongest role as primary, masking many gaps; existing/directly seeded memberships still need consistent authorization. A forward migration is prepared in this QA pass; live deployment is separate.
2. **Regular SLA recipient gap:** `auto_urgent/TicketEscalate.sql` overdue branch only notifies primary assignee and primary admin/superadmin; seven-day urgent branch handles additional assignees/roles. SLA alerts for secondary agents/multi-role staff need reconciliation.
3. **Large JSON aggregation risk:** TicketShow, TicketChatRead, analytics and inventory show construct JSON with GROUP_CONCAT. No source setting for group_concat_max_len. Live MySQL value unknown; low limit can truncate and trigger JSON_THROW_ON_ERROR500. Test long isolated comment/history or inspect server value read-only.
4. **Conversation pagination missing in Vue:** chat API returns100 and has_more, but store fetchChat always requests after0 and discards has_more; later messages can become invisible on busy tickets. Presence API exists but Vue does not send typing/seen updates.
5. **Reopen UI is overly broad:** visible for every resolved/closed ticket regardless tickets.reopen/ownership; endpoint only permits requester-owned ticket. Staff reopening other's ticket through this button fails while PATCH status may work.
6. **Audit history is latest100 only:** date/search filters do not query older records; no audit pagination endpoint.
7. **Passkey origin mismatch and missing management UI:** Fortify supports passkeys/2FA, Vue supports 2FA login challenge only. Backend RP cannot be used from separate pages.dev origin without configuration/design change.
8. **Upload durability requires environment validation:** proof/ticket files and avatars use local container disks. If Render deployment lacks persistent disk, database attachment metadata survives redeploy but bytes do not. Source inspection alone cannot prove deployment storage settings.

9. **Confirmed local MySQL assignment failure:** the previous TicketUpdateAgents body referenced its temporary table twice in one statement, producing error1137 `Can't reopen table: incoming` during multi-agent assignment on MySQL8.4.11. Replacement SQL compares additions/removals in separate statements. Aiven/live behavior has not been tested by this agent.

These findings distinguish code behavior and local regression results from live outcomes. Do not count an unexecuted deployed case as passed or infer actual email receipt from SMTP acceptance.
